# Dab's Mod patch notes: what got fixed, and who reported it.
#
# The game shows these on Check for Updates (what an update brings, or what is
# new in the running build) and, once after an update, on the main menu. The
# build carries its own copy from when it was configured; the release job
# uploads this file next to update.txt, and Check for Updates fetches it from
# there. See port/src/patchnotes.c.
#
# HOW TO ADD AN ENTRY (at each merge onto dabs-mod that fixes something):
#
#   1. Add a new "notes" line ABOVE the newest entry:
#          notes <number> <date>
#      The number is one more than the highest one in the file, the date is
#      YYYY-MM-DD. A build knows which notes it already has by that number, so
#      every batch that gets pushed needs its own number. Never renumber, and
#      never add lines to an entry that has already been pushed: a player who
#      has that build has seen it, and will not be shown what was added.
#   2. Under it, one line per fix, in the words a player would use: where it
#      happens, then what is different now. Short - one line, not a paragraph.
#          Chicago: the patrol robot's shots no longer freeze in mid-air (thanks Parabolee)
#   3. Credit the tester with "(thanks Name)" at the end, Name exactly as the
#      report's "name:" field (or the name they typed into the note) spells
#      it. A report with no name gets no credit. Never an IP address, a report
#      stamp or a commit hash - the game drops any line with an IP address in
#      it, but do not rely on that.
#   4. One blank line between entries. Lines starting with # are ignored, and
#      so is anything above the first "notes" line.
#   5. Plain ASCII only (no curly quotes or dashes: the menu font has none),
#      and no "|" (the menu uses it to start a heading).
#
# CMake reads the newest number when it configures, and configures again by
# itself when this file changes, so an ordinary rebuild picks up an entry.
