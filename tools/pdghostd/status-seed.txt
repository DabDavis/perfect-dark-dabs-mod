# What became of each problem report - read by pdghostd's report board
# (GET /board, https://texturepacks.art/pdghosts/board). Lives on the server as
# ~/pdghosts/reports/status.txt and is edited by hand at each pass over the
# reports; the board picks up a change on its next request, no restart.
#
# One report a line:
#
#     <report id> <status> [<when>] <public comment...>
#
#   report id  the report's file name without .txt (20260925-224209-e9d359f1),
#              or its stamp alone (20260925-224209) for every report sent in
#              that second. A full id's line beats a stamp's.
#   status     received  - looked at or not, nothing to say yet (the default:
#                          a report with no line here, or no file at all)
#              working   - in progress; "Fixed, in the next update - ..." for
#                          a fix that is committed but not shipped
#              fixed     - shipped in a deployed build. Say when (below):
#                          it places the fix in the Fixed column.
#              needinfo  - waiting on the tester for more
#              notabug   - works as intended (say why in the comment)
#              wontfix   - a decision not to change it
#              duplicate - the comment starts with the other report's id; if
#                          that one is fixed, this one is credited with it
#              hidden    - taken off the board altogether (spam, or a note
#                          that should not be public); the report is kept
#   when       only "fixed" uses it, in one of two forms:
#              <batch>.<line>  the line of the patch notes that announced the
#                          fix - 1.17 is the 17th fix line under "notes 1" in
#                          patchnotes.txt (the repo's, copied beside this file
#                          as ~/pdghosts/reports/patchnotes.txt). The Fixed
#                          column then shows that line's words, date and
#                          "(thanks ...)"; the comment need only be
#                          "Fixed in <build>", and the report's card reads
#                          "Fixed in <build> - <the patch notes line>".
#                          Batches never change once pushed, so the number
#                          stays right. Preferred: each fix is written once.
#              YYYY-MM-DD  the date it shipped, for a fix the patch notes do
#                          not announce; then write the whole comment as
#                          "Fixed in <build> - <where>: <what>", and give
#                          every report fixed by the SAME change the
#                          identical date and comment - the Fixed column
#                          shows them as one entry crediting all senders.
#   comment    one line, shown to everyone - plain words, no IPs, no paths,
#              no function names. Report ids in it become links.
#
# A later line for the same report replaces an earlier one. Lines starting
# with # and lines the board cannot read are ignored (a typo costs its line).
