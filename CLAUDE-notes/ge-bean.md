# GoldenEye 007 XBLA ("Project Bean") characters on GoldenEye X (2026-09-15)

`port/src/gebean.c`, `Mod.XblaGoldenEye`, "Enable GoldenEye Characters" on
the Xbox 360 (XBLA) page, default off.

The GoldenEye archive in circulation (`GoldenEye_007_XBLA.7z`, 242MB, one
solid LZMA2 block of 740MB) is Rare's 2007 Xbox 360 devkit build, CAFF
07.08.06.0036 - **nothing from the Perfect Dark release's STFS, Textures.raw or
PackedSegFile code applies to it.** The player drops it in `xbla/` beside the
Perfect Dark one, as the archive or the folder it unpacks to (the one with
`default.xex` and `files/`). An archive's `char/` and `head/` folders of
`files/new/` and `files/original/` - 244 files, 84MB - are streamed into
`cache/xbla/goldeneye/` once, at the first level load that wants a character.

The research that got here (formats, the offline batch, the texture
comparison) is in the session memory `ge-xbla-bean-assets` and the scripts in
`.xbla-work/ge-bean/`. This note is what the port does and what it cost to
find out.

## Which GoldenEye X file is which character

GoldenEye X keeps GoldenEye's N64 vertices byte for byte under Perfect Dark's
file names (`CsecretaryZ` is Natalya), so the pairing was made offline against
the GE decomp's arrays and settled by texture where GoldenEye used one mesh for
several outfits. The port carries the answer: `port/src/gebeantable.h`,
generated by `.xbla-work/ge-bean/gen_beantable.py` from `gemap.json`,
`gexassign.json` and `texcompare.json` with `batch_gex.py`'s rules.
Regenerate it rather than editing it.

A row is the file name, **its list node count and total vertex count**, the
kind and the Bean asset. `gebeanFindRow()` takes a row only for a *mod's* file
(`romdataFileIsStock()` false) whose name and both counts match, so another
mod's `CsecretaryZ` is left alone and says so in the log.

Kinds:

- `GEBEAN_BODY` - a generic body (guard, Bond, civilian). Bean's built-in head
  is dropped and the body's neck lists are **absent** from the mesh, so the N64
  neck stub keeps drawing under whichever head GoldenEye X grafts on.
- `GEBEAN_BODY_WITH_HEAD` - GoldenEye drew this character's head as part of
  the body and GoldenEye X moved it to a head file (Natalya, Xenia, Jaws...).
  The body's neck lists get a **degenerate triangle** so the N64 neck draws
  nothing under Bean's neck, which the head file carries.
- `GEBEAN_HEAD` - a head file, from a character's neck triangles (`char/...`)
  or a Bean head file (`head/...`). Toggled lists (glasses, hats, second hair)
  get a degenerate triangle: Bean's head already has them.

Left out on purpose, all decided in the batch: Bean's blueman, bluewoman and
greyman (broken in the release itself - greatguard2's atlas on blueman's
mesh), heads GoldenEye X made up (keith, griffey, tintin, christ), ties, and the
Bond heads (Bean's are static N64-style models, not skinned HD heads).

## The files

A CAFF bundle: header (big-endian flag at 0x48, section count at 0x49,
compression at 0x4a - always 0 here), a 0x21 byte entry per section, the asset
name table, one more table skipped by its length, then a 14 byte record per
file `{asset, start, size, section}`. Section data follows in section order
from `hsize + sectsize + filesize`. `caffOpen()`.

Asset 1 is the rendergraph: `.data`, `.gpu` (vertex and index buffers),
`.stream` (commands). Asset 2's `.data` is a string pool whose `SKEL_*` names
are the pose bones in order. The command stream, first alternative at every
switch: `0x12` palette remap `{u16 n, 0, n x {u16 bone, ffff, 4}}`, `0x13` bone
palette `{u16 n, 0, n bytes}`, `0x16` switch, `0x19` jump, `0x1d` end, `0x2d`
material (texture index in word 3 when the record is 20 bytes, word 5
otherwise), `0x2e` vertex buffer, `0x01` draw `{D3D prim 4/5/13, count, IB}`.
A vertex slot is palette slot `s/3`, the palette gives a number, the remap
table a pose bone. The index buffer object is found by its table row
`{obj, off, size, 1}` in `.data`.

Two traps, both from the batch and both kept in the C:

- **The UV scale is not in the file.** Rare exported s16 UVs at 1/16384 for
  the uniformed guards, the pilot, Xenia, Boris and six heads, and 1/32768 for
  the rest. The largest UV is at most 16404 in the first group and at least
  32031 in the second, so `beanMeasureUvScale()` decides from that. Wrong, a
  model samples the top-left quarter of its atlas (black guards).
- **A vertex buffer is shared by draws with different palettes.** A vertex is
  taken once per draw, never once per buffer.

Textures are D3D headers: format byte `0x1b` (`0x52/0x53/0x54` DXT1/3/5, `0x86`
8888; `0x40` is the tiled bit, so the low six bits are the GPU format
`x360DecodeTexture()` already knows), 8-in-16 swap when byte `0x1a` is set,
width and height at `0x24`. The texels are the asset's own `.gpu` entry, or,
where it has none (Oddjob), the file's `texture pairs` `.gpu` entry at the base
offset in `0x28`. A file can stop short of the whole tiled surface, so the copy
is padded. Decoded top row first and flipped for the renderer, as
`modelpackBindMaterial()` does a PNG. Bound once per character through
`xblaTexBindImage()`, keyed `gebean:<source>:<n>`.

## The mesh

`gebeanBuild()` writes 4J's mesh layout (xbla.md, "The mesh format"), so
`xblaMeshBuildFile()` builds it and the pose, fineness, reflections and
translucent spans all apply unchanged.

- **The rig.** The model's joints are read off its tree: the chrinfo root is
  `SKEL_BASE`; a position node within 30 units of the middle line is the back
  below y 200 and the neck above; the rest are three per limb, arm above y
  200, left where x is positive, ordered outwards. That is GoldenEye's **star
  rest pose** (arms out, legs splayed along x). Natalya's: chrinfo matrix 4,
  back 1, neck 0 (the headspot hangs under it), limbs 2/11/12, 3/13/14, 5/6/7,
  8/9/10.
- **The fit.** Each Bean bone is turned so its segment (bone to child) lies
  along the rig's, ends turning with their parent, and scaled by the ratio of
  the two skeletons' limb lengths - 0.2130 on every body. A vertex's position
  is each of its bones' reading of it on the rig, blended by weight.
- **The skin.** The palette is the model's `nummatrices` entries, **each an
  identity turn with the joint's rest position taken back off**, because the
  rest pose has no rotations; so palette entry i is matrix i, the rule the
  release's meshes follow. A vertex keeps Bean's up-to-four bones as matrices,
  merged where two share one, the three heaviest renormalised.
- **The groups.** One per list node. A triangle goes to every node of its
  dominant bone - near and far LOD alike, since the game draws one of the two.
- **Heads** are rigid: one palette entry, identity, vertices in the head file's
  own space (origin at the neck joint). A head taken from a whole character is
  turned so Bean's spine points straight up, which GoldenEye's does to a third
  of a degree; a Bean head file stands as it is. Scale 0.213, since a head file
  has no skeleton to measure. That one entry is posed by matrix 0, which is the
  body's neck when grafted and the head's own matrix on the Character page.

This is what removed the knee and elbow creases of the model pack route
(`bean2pack.py`), which could only give each triangle to one rigid list.

## How it is drawn

`xblamesh.c` files a Bean row beside the model pack's side of every node
(`xblaMeshRegisterPackModel()`, now run when there is a pack **or** a row),
`e->beanrow` plus the pack's `packpart`/`packuse`, and fills the use's
`partmtx` from `gebeanListNodeMatrix()`. At the draw a node takes the Bean mesh
when the switch is on and neither the release's mesh nor a pack's file wants
it; `xblaMeshBuildBean()` builds it once per file id and keeps it across
stages. The group is chosen by `packpart` with `groupabsent`, like a pack's
file, and the pose uses the use, like a release mesh.

Not reached by a Bean mesh, and why that is fine for now: the bruise map (keyed
on the release's slot) and the triangle hit test (`e->matched` only), so shots
test the N64 triangles the lists still hold, exactly as for a pack's file.

The F3 trace names a Bean node, its row and whether the switch is on.

## The archive

`archiveExtractMatching()` streams a solid 7z block made by one LZMA or LZMA2
coder straight into the wanted files, holding the dictionary (64MB) and never
the block; `SzArEx_Extract()` would allocate all 740MB to write 60MB. Any other
kind of block falls back to the SDK. `archiveFindEntry()` reads only the
directory, and **`xblaimport.c`'s scan uses it to skip an archive holding
`files/new/char/`** - before that, the first `.7z` in `xbla/` was taken as the
Perfect Dark release whatever it held.

## Test recipe

A run directory of its own, so `build/` and its `xbla/` are not touched: a copy
of `pd.x86_64` (`$E` follows the real executable, so a symlink will not do),
`data` and `mods` symlinked, and `xbla/GoldenEye` a symlink to the unpacked
`Bean` folder (or the `.7z` itself, to test the unpack). Scratch save with
`Mod.XblaGoldenEye=1` and `Mod.LoadModels=0` (**a `bean` model pack on disk
wins over the native loader** otherwise). Then:

```sh
SDL_VIDEODRIVER=offscreen gdb -batch -x survey.gdb --args ./pd.x86_64 \
    --moddir mods/GE-X_6a_01-19-25 --savedir SAVE --skip-intro --no-sound \
    --boot-stage 0x1f --mpsims 8 --endless --spectate --fixed-step --rng-seed 1 --log
```

with a `lvReset` breakpoint that sets `g_BotConfigsArray[i].base.mpbodynum`
(and `mpheadnum` from `mpGetMpheadnumByMpbodynum()`), and from frame 398 moves
`g_Vars.currentplayer->prop->pos` 230 units behind simulant `g_MpAllChrPtrs[k]`,
`vv_theta 0`, with a `screenshotRequest()` three frames later. Mpbody 5 is
Natalya. The log's `gebean: <file> <- <source>` lines say what built, and at
what scale. A shot every four frames misses when the camera lands in a wall;
the hover cart in front of the spectator is the player's own.

## In Perfect Dark's own Combat Simulator lists (2026-09-15)

`gebeanPoolRefresh()` appends 38 GoldenEye characters and 28 heads to
`g_MpBodies`/`g_MpHeads` (61 -> 99, 75 -> 103; both inside the MP save's 7 bits)
when the switch is on, a copy is in `xbla/` and the lists are stock length. A
mod's lists (GE-X) keep them out. It runs at boot, after `modListSwap()` and on
the checkbox. Names and default heads are GoldenEye's `mp_chr_setup[]`; a body's
model is read off the decomp's body enum zipped with `chrobjdata.h`'s header
order (camguard = Jungle Commando, greyguard = St. Petersburg Guard, ...).

- **No GoldenEye N64 model is needed.** Perfect Dark's bodies stand in the same
  star rest (Cdd_guardZ's arms reach x +-1000), so the rig reader fits Bean onto
  them: Joanna for women (15 lists), the dataDyne guard for men (30), heads on
  CheadjamieZ/CheadankaZ. The body scale fits to ~0.193 against GE-X's 0.213;
  heads keep 0.213 and may read slightly large - not judged up close yet.
- **Each character is its own file number**: `romdataRegisterAliasFile()` gives
  a slot, taken from the top of the table down, that serves the host's
  contents. A row keeps its own modeldef, the Bean cache (keyed on file id)
  stays apart, and an alias is not stock, so the release matcher leaves it
  alone. `romdataResetFiles()` empties aliases, hence the refresh after a swap.
- Rows are `g_HeadsAndBodies[152..]`, now 256 long on PC; `bodiesReset()` clears
  all 256 (the stock loop stopped at the terminator and would have left stale
  modeldefs). **`chrdata.headnum` is s16 on PC**: it was s8 and a head row past
  127 went negative.
- `GEBEAN_WHOLE`: a character GoldenEye drew with its own head (Natalya, Jaws,
  the pilot...) is built whole on a body row with `unk00_01` set, so it takes no
  head and needs no head row.
- Names come from `gebeanPoolBodyName()` in `mpGetBodyName()`; there are no
  text ids.
- rusguard, techwoman, jeanwoman and fattechwoman were never in GE-X's batch;
  techwoman and rusguard built and drew in the survey, the other two have not
  been looked at.

## Walking the Carrington Institute as one (2026-09-15)

The Perfect Menu's **Customize Character** (between Carrington Institute and
Solo Missions) opens `g_CiCharacterMenuDialog` (ghostmenu.c), the trial
page's carousels over `g_ModCiBody`/`g_ModCiHead` (`Mod.InstituteCharacter`,
`Mod.InstituteCharacterHead`; body index plus one, 0 = Joanna). It is kept apart
from the trial character, which ghostnet.c swaps with the signed-in account.
`playerChooseBodyAndHead()` takes it for the solo player on `STAGE_CITRAINING`
(`modGhostGetInstituteCharacter()`), with a private head copy as a trial gets.
Every change raises `modGhostMarkInstituteBodyStale()`, which
`playerTickChrBody()` takes beside the spectator's mark, so the body is rebuilt
live without a reload. `MODGHOST_MAXBODIES` and `Mod.GhostCharacter`'s clamp
went from 64/61 to `MAX_MPBODIES`. Past the old table the default head was
asked afresh every frame, and the preview of a GoldenEye body never loaded.

Checked headless (`--boot-stage 0x26`, scratch `ci.gdb`): the row and the page
draw, with Natalya turning in the preview; the player's chr is body 152 with
head -1 in third person; setting Jaws and raising the mark rebuilt it as 159
(file 3064 loaded) mid-level. Forcing `g_FileState` and `menuStop()` from gdb
brings "Choose Your Reality" straight back. Seeing the walk needs the
Xvfb/xdotool agent-file route (memory `headless-game-driving`).

## The N64 look on F6 (2026-09-15)

Bean shipped its characters twice: HD in `files/new/` and the N64-look ones
Bean itself switched to in `files/original/`, same names, same CAFF
rendergraph, same 16-bone `SKEL_*` skeleton. So F6 moves a GoldenEye character
with the rest of the release: the draw (`xblaMeshRenderNode()`) builds
`gebeanBuild(row, original = !Mod.XblaMeshes)`, cached per look
(`beanBuilt[look][fileid]`), textures keyed `gebean:<look>/<source>:<n>`.

- **A pool row** (Perfect Dark's Combat Simulator, `gebeanRowIsPool()`) takes
  `original/` with the meshes off.
- **A GoldenEye X row** takes nothing with the meshes off: GoldenEye X's own
  model is GoldenEye's N64 geometry byte for byte, and draws itself.
- The archive filter takes `files/original/char/` and `head/` too, and the
  done marker is `.extracted2`, so a cache unpacked before (new/ only) is
  unpacked once more.

What the originals needed, all found by rendering every file offline
(`bean2obj.py` with a patched walker) before touching the C:

- **The UV scale is a per-file power of two from 2048 to 16384** (tuxedo Bond
  2048, uniformed guards 4096, most heads 8192, Natalya 16384), not the HD
  files' 16384/32768, and some N64 textures wrap well past one repeat, which
  the old "largest UV in the file" rule read as 32768. Nothing in the material
  records says which (every 0x2d is `00010000 ... 0`). `beanMeasureUvScale()`
  now takes each texture's largest UV over its own triangles (skipping 1x1
  untextured spans), and the smallest power of two within a quarter of the
  median. It gives the old answer on all 67 HD files the port uses.
- **0x30 is a second draw record** `{prim, count, IB object, flag}`, only in
  the originals (41 files). Flag 0 is the character; heads' flag 1 and 2 draws
  are extras (sunglasses arms). Taken when the flag is 0.
- **0x17 `{kind, end}` guards a section.** Kind 0 is in both sets and drawn,
  as always. Kind 2 is only in the originals, round 22 heads' sunglasses, which
  GoldenEye's multiplayer heads do not wear: skipped.
- **Original head files weight the face to BACK as often as NECK** (Head B,
  Joel, Sally...), and Dave's has no palette at all (stride 24). For an
  original head file BACK and unskinned triangles count as the neck; its only
  other bones are Head B's stray pair of shoes a body's height below, which
  stay dropped. Original bodies weight their own heads to NECK, like HD.
- **Karl, Martin, Duncan and Dwayne's original heads** name their bones
  `SKEL_*_P_` and carry a pose of zeros while the vertices stand where every
  head's do; the neck and back are taken from the same head's `new/` file.

Checked headless on 0x32 with the pool (bodies 61-68, 73-80, 81-88, scratch
`look.gdb`/`face_up.gdb`: eight bodies, a pass, `xblaSwitchSetEnabled(1)` at
frame 432, the same pass again): every row built in both looks, originals at
~1000 vertices against ~2500, heads seated with no glasses. Offline renders of
the originals are the quickest check of a walker change - the in-game camera
at `pos.y + 0` frames the waist, `+ 70` the face.
